# Batch reports

`process <paths...>` prints a text summary and ordered per-recording outcomes with stage timings. `--json` emits one UTF-8 JSON document on stdout: `schemaVersion: 1`, `batch` containing UTC `startedAt`/`endedAt`, `dryRun`, `interrupted`, `completeDiscovery`, totals, `exitCode` and `recordings`. Logs and progress go to stderr.

Each recording contains a zero-based discovery `ordinal`, canonical `path`, `outcome`, static `reasonCode`, nonnegative `elapsedMillis`, and `stageTimings` (`stage`, `elapsedMillis`). Recording elapsed time starts when its worker begins, excluding queue wait. Stage timing includes the history boundary and its operation, uses a monotonic clock, and is isolated per worker. Repeated stages remain separate. Dry-run has no persisted stages and currently reports an empty stageTimings list. Input order is preserved across concurrent completion; directory entries are sorted by name. Multiple occurrences of the same path retain separate entries and use durable job claims to avoid duplicate processing.

Outcomes are SUBMITTED (encoding queued, not encoding completed), SKIPPED_ALREADY_REGISTERED, DRY_RUN, FAILED, INTERRUPTED, NOT_STARTED. Unknown errors use PROCESSING_FAILED without raw exception messages. Missing/nonregular/inaccessible input is an explicit failure; an empty readable directory is an empty successful batch. `completeDiscovery: false` means cancellation stopped enumeration: unobserved inputs are not invented in the report. Admitted but unstarted work is NOT_STARTED; started unfinished work is INTERRUPTED. Forceful JVM/process termination may prevent final JSON from being emitted; a missing report is not success.

Exit codes: 0 for all submitted/skipped/dry-run or empty; 1 for wholly failed/operational/incomplete work; 4 for a mixture of successful/skipped/planned and failed inputs; 130 for cooperative interruption. Native SIGTERM normally remains 143. Existing per-file process failures that previously returned 1 now return 4 only when mixed with successful results. JSON is emitted before a nonzero batch exit whenever a report is available.

`--slack per-file|summary|none` selects notification policy (default per-file preserves existing failure notices). Summary suppresses per-file notices and sends one totals-only notification for a settled noninterrupted batch. None suppresses notifications originating from that batch. Dry-run never sends Slack. Interrupted batches skip network summary delivery so reporting cannot delay shutdown; per-file notices already sent are not recalled. Slack failures do not turn processed recordings into failures. No configured webhook remains a no-op.

The existing bounded worker queue and independent stage limits still apply. Report memory is proportional to discovered input count. On cancellation workers are interrupted, queued tasks are discarded, and settlement waits no longer than `processor.shutdown.grace-seconds`; the existing native shutdown hook retains its overall deadline. Snapshot results remain immutable after return, even if a noncooperative dependency outlives that bound. Quality quarantine belongs to a separate stack: integration must preserve its hold outcome and exit4 instead of treating it as SUBMITTED.

External tool output from noncapturing shell execution (TsSplitter and encoder submission) is streamed to stderr, including the child's stdout. Capturing execution (ffprobe) continues to return separate stdout/stderr to its caller. Neither path changes owned process teardown or timeout limits.
