# 処理の事前チェック (preflight)

`tvpcli preflight [--json] [--dry-run | --check-write] <file-or-directory>...` は、doctor と共通の設定/データベース/NAS の結果に、入力・ツール・エンコーダ・容量のチェックを加えて集約する。ディレクトリは、通常の `.m2ts` ファイルをファイル名順に展開する (再帰しない。大文字小文字を区別し、`.M2TS` はパイプラインと同様にスキップされる)。スキーマのマイグレーションは不要。

パッケージ版の通常の `process` は、ドライランも含め、通常の Spring の processor グラフの前にこのバッチチェックを実行する。FAIL があると、検査・登録・分割・圧縮・投入は止まる。低レベルのパイプライン/ランナーを組み込みで呼び出す場合は、呼び出し側が `ProcessingPreflightCommand` を自分で呼ぶ必要がある。チェックは、その時点での観測であり、ロックでも、後の変更に対する保証でもない。

入力は、正規パスで読み取り可能な通常ファイルでなければならない。存在しない/読み取れないファイルや、空のディレクトリは失敗になる。ツールの設定 (`TS_SPLITTER_PATH`、`AMATSUKAZE_ADD_TASK_PATH`、`FFPROBE_PATH`) は読み取り可能なファイルを指す必要があり、名前だけの場合は PATH から解決される。ffprobe は Unix で実行権限が必要。TsSplitter/Amatsukaze は Windows 専用で、他のプラットフォームではアクセス可能性のチェックは通るが、実行可能かどうかは明示的に UNCHECKED となる。preflight がツールを起動することはない。Windows の実行ファイルとしての妥当性や、リモートのプロファイルの存在は推測しない。

エンコーダのホスト/ポートと、既定/AT-X のプロファイル名はローカルで検証される。ホストは DNS 名または IPv4 リテラル (LAN/Windows の名前のためにアンダースコアを許可)、または角括弧付きの IPv6 リテラルである。3 秒の DNS+TCP の呼び出し側デッドラインで接続性のみを確認し、エンコーダのプロトコルやタスクの受け付けは確認しない。一部のネイティブリゾルバは強制的に中断できないため、DNS にはデーモンのワーカーを使う。リゾルバが止まっても CLI が生き続けることはない。

ローカルの一時領域の見積もりは、既定ではファイルシステムごとに**入力の合計バイト数の 3 倍**である。外部の Spring YAML の `processor-preflight.space-multiplier` または `PROCESSOR_PREFLIGHT_SPACE_MULTIPLIER` で設定でき、有限の正の値でなければならない。正規パスが同じエイリアスは 1 回だけ数え、FileStore を共有するディレクトリは 1 つの合算した見積もりを共有する。空でない入力に対して実際の空き容量が 0 の場合は失敗し、API の失敗は UNCHECKED、オーバーフローは明示的に失敗となる。見積もりは切り上げられる。これは予約でも、実際の圧縮/エンコード量の予測でもない。外部のエンコーダの出力ボリュームは別途確認すること。

既定のチェックは読み取り専用である。明示的な `--check-write` は、doctor の一意で排他的な NAS の作成/書き込み/読み取り/削除のプローブを再利用する。ドライランおよび通常の process では使用できない。クリーンアップの失敗は報告され、所有が不明確な作成は自動で削除されることはない。

JSON の標準出力は UTF-8 で、`schemaVersion: 1` と、`id`、`status` (PASS/FAIL/UNCHECKED)、安全で対処可能な `reason` を持つ `checks` を含む。認証情報を含む設定や生の例外はエコーされない。ユーザーが指定した入力の正規パスは表示されるため、ホストの外で共有された JSON (または転送されたスケジュールジョブの出力) には録画のパスが含まれる。環境変数のみの Boot 設定読み込みにより、通常の Bean グラフの前に不正なデータソース/ツールの設定を診断する。外部の YAML には `--spring.config.additional-location=<file>` を使う (プロパティになるのは `--spring.key=value` の形式のみで、`--spring.key value` は違う。`--` 以降の引数は常にオペランドとして扱われる)。終了コード: 0 は FAIL なし (UNCHECKED は残ることがある)、1 はチェック失敗、2 は CLI の指定が不正、130 は中断。共有の DB/NAS のタイムアウトは 1 操作あたり 3 秒で、合計時間はすべてのエンドポイントを含む。

Windows 専用のツール (および Windows 上のすべてのツール) の PASS は、ファイルが読み取り可能であることを意味し、実行権限はチェックされない。TsSplitter と圧縮は出力を入力の隣に書くため、容量の見積もりは各入力を保持するファイルシステムを使う。

`--json`/`--help` は `--` の区切りより前でのみ認識されるため、`tvpcli process -- --json` は `--json` をパスとして扱う。preflight 自体が予期せず失敗した場合、stderr には例外のクラス名のみが出力され (メッセージは出力されない)、設定を漏らさずにバグを診断できる。

`scripts/preflight-cli-smoke.py` は、専用の MariaDB と Samba のインスタンスに対して、パッケージ済みの CLI をエンドツーエンドで実行する。これは手動チェックであり、CI や `./gradlew test` では実行されない。
