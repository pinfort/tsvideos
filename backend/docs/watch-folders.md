# Watch completed recordings

Run `tvpcli watch /recordings/channel-a /recordings/channel-b --completion marker --poll-seconds 5` to prefer an explicit completion signal. Directories are required positional arguments (maximum 32). `--extension .m2ts` is the default; repeat the option for other extensions such as `.ts`. Matching is case-insensitive. Only direct regular files are eligible: there is no recursive traversal, directory symlinks are rejected, and file/marker symlinks are not followed. Missing or inaccessible directories do not stop healthy ones; each is rescanned with independent exponential backoff capped at 60 seconds. Polling discovers files already present at startup as well as later arrivals.

Completion policy must be explicitly selected:

- `--completion marker`: a regular non-symlink sidecar named `<input>.ready` must exist with modification time at least as new as the input. Customize the suffix with `--marker-suffix .done`. The recorder should finish and close the recording before publishing the marker. Watch never removes source files or markers itself; accepted processing retains the established pipeline’s verified-upload/original protection behavior.
- `--completion stable --stable-seconds 30`: the same canonical path, size and modification time must appear in at least two different polls separated by the full monotonic stability interval. This cannot prove a writer has closed its file; constant-size writes, coarse/restored timestamps and TOCTOU changes can evade metadata detection. Prefer markers when the recorder can provide them. Poll/stability intervals accept positive whole seconds (`--poll-seconds` 1..3600, `--stable-seconds` 1..86400).

The observed fingerprint is checked before queue admission, at worker start, and again by the pipeline before its durable claim. Changed queued inputs must restabilize. These checks are not filesystem locks, content hashes or proof of writer ownership, and markers may change immediately after a check.

One outer cancellation owner and one executor live for the entire watch invocation. The worker/queue/stage limits from parallel-processing.md apply; the scanner blocks on the bounded queue. It advances one directory entry per directory per round and rotates the starting directory, so a large directory does not get an exclusive scan pass. Every existing durable job state, including RETRYABLE, CLAIMED and SUBMISSION_UNKNOWN, suppresses watch processing across restarts. Watch does not guess that an old owner died or automatically retry transient failures. Reconcile/reset/process explicitly as appropriate; #65 owns future retry policy.

`--dry-run` performs only directory/metadata reads and prints WATCH_READY_DRY_RUN once per observed ready version in this invocation. It does not call processing tools, claim jobs, write history, create files or remove markers. A new dry-run invocation may report those versions again.

Both pending stability observations and admitted-version history are bounded by `--max-observations` (default 10000, range 1..100000). Retaining admitted versions prevents repeated plans and retry loops after failures before a claim. Disappeared unready observations are discarded after a scan. If capacity is exhausted, watch emits WATCH_CAPACITY_EXCEEDED, stops admitting inputs, drains already queued/running work normally and exits 4. Restart or raise the limit explicitly; monitoring does not silently continue ignoring new recordings. Completed/admitted versions remain counted for this invocation, including successful normal processing.

SIGINT/SIGTERM stop scanning/admission, discard unstarted queued work, and interrupt all workers with the shared shutdown deadline (default 30 seconds). Existing graceful-shutdown.md guarantees and hard-kill limitations apply. Caught interruption exits 130; native SIGTERM commonly exits 143. Invalid CLI configuration exits 2, capacity exhaustion exits 4; individual processing failures are reported independently and monitoring continues without retrying that version. Diagnostics expose fixed codes rather than external exception messages.
