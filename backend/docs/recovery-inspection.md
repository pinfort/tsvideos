# Recovery inspection and planning

`tvpcli inspect --job-id 12 [--json]` correlates durable jobs, database registrations, checkpoints, callback inputs, retained history and local/NAS evidence. Alternatively select `--recording /absolute/path/recording.m2ts`. Exactly one selector is required. Missing originals can be resolved through stored canonical paths. Multiple versions are reported as ambiguous; select a job explicitly. A deleted symlink alias cannot reliably be canonicalized to its former target: use the stored path or job ID. Legacy registrations are displayed without inventing a job; automatic resume remains blocked without durable evidence.

`tvpcli recover --job-id 12 --dry-run [--json]` returns the same evidence and an explicit resume command argument list when the existing resume validator permits it. `--dry-run` is mandatory before any inspection. Neither command acquires ownership, executes resume/reset, writes history, uploads, registers, removes files or changes database rows. Inspecting is a snapshot, not a reservation; concurrent changes are possible and resume revalidates independently.

Local PRESENT means the path was observed as a regular file. NONE is existence-only evidence, METADATA checks the recorded size/mtime, and SHA256 checks immutable checkpoint content. MISSING is a confirmed absent path; INACCESSIBLE means observation failed; UNCHECKED means the target is not a regular file. CHANGED records a mismatch. Missing outputs already deleted after verified upload can be legitimate: only the shared resume plan decides whether they prevent recovery. A missing original while waiting for callback requires a registered archive with verified checksum; without that evidence it requires attention.

Registered NAS artifacts use the shared library verifier: VERIFIED/SIZE_ONLY is metadata verification, not a checksum receipt. MISSING requires completed storage observations; inaccessible storage stays INACCESSIBLE. Incomplete transfers and manifests without verified receipts remain UNCHECKED. Uploads expose state, exact relative final/temporary paths, source path and an ownership-present boolean, never claim tokens. SHA256_RECEIPT denotes the corresponding successful validation by the shared recovery plan. Invalid credential-bearing NAS URLs are redacted. DB registrations without a program explicitly report unchecked NAS artifacts and inconsistency.

Stages show COMPLETED only for a validated skip; INPUT and CALLBACK_CONTEXT skips are PREREQUISITE_VERIFIED. Remaining work is INCOMPLETE. Normal SUBMITTED callback wait is WAITING, distinct from inconsistent evidence. Active ownership and SUBMISSION_UNKNOWN require manual reconciliation; no elapsed-time reclaim or encoder resubmission is inferred. Reset is only a conditional manual option after ownership/encoder reconciliation: it preserves the original recording and deletes generated local/NAS artifacts and registrations. These commands never execute it.

JSON schemaVersion 1 contains `operation`, `dryRun: true`, and `inspection`: selection/candidateJobIds, jobState/status, database records, localArtifacts/nasArtifacts, upload evidence, immutable checkpoints/callback input, stage actions/prerequisites, history summary, resumePossible/resumeCommand and manualOptions. Diagnostic exception text and credentials are excluded. Exit codes: 0 usable or normal inspect wait; 3 unknown identity; 4 blocked/ambiguous/inconsistent, including recover while waiting; 2 invalid selectors or missing recover --dry-run; 1 operational failure; 130 interruption. Logs remain on stderr.

This feature directly depends on resumable processing (#63) and integrates the shared library verifier (#58, PR78). It does not provide automatic recovery execution.
